# 开发与验收计划

基线 V2 已实机 8 人；Core Lab 已实机报告。下一阶段不直接编写完整产品，先解决服务链路是否可用。

| 阶段 | 验收门槛 |
|---|---|
| 0 授权网络实验 | 由管理方明确允许客户端、服务及必要网络访问；在自有测试网络验证 |
| 1 Core Lab 连接 | 对指定获准服务完成 GET/POST、WS/WSS Echo；记录真实响应和错误，验证TLS证书 |
| 2 ESP32最小服务 | Wi-Fi、健康状态、资源记录；1个客户端双向消息，无 AI |
| 3 常驻房间 | 2→8人；任意客户端退出重开、重新认证、恢复授权历史；重复发送去重 |
| 4 持久化 | 重启、断电恢复、有限日志与容量；验证不影响聊天 |
| 5 iPad Console | 鉴权与角色拒绝测试；在线状态与操作审计 |
| 6 AI Gateway | 单个授权 API 调用；多请求队列、配额、取消、超时；AI失败不阻塞聊天 |
| 7 稳定性 | 8小时、24小时；2/8/16/32逐级测试，超容量拒绝；不能预先宣称通过 |
| 8 扩展 | 私聊、图片小文件、白板、投票、游戏，按需求逐个验收 |

记录指标：连接成功率、在线峰值、应用消息 ACK、真实跨设备 RTT p50/p95/max、丢失/重复/乱序、重连耗时、内部堆最小余量、PSRAM、最大队列、Flash 写入量、温度和复位原因。明确样本数、测试负载、网络与固件版本，区分回环/跨设备/ESP32。现有实测仅短时、8台操作者报告，不足以支持容量或 SLA 承诺。
