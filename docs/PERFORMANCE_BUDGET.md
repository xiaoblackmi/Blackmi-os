# Blackmi OS PAD 性能预算（初始建议）

依据 Hardware Lab V2.0 批次 mwzt8gbr（960×600、DPR2，短时合成负载）；不是已验证的游戏上限。适用 V3.2.1 后续开发，834×360 必须额外实测。通信 Transport、ICE/SDP、QR、握手等冻结，不因预算改协议。

| 项目 | 初始目标 | 理由 |
|---|---|---|
| 实时游戏 | 目标60 FPS，低负载档至少稳定30 FPS；关注 P95 帧间隔≤33.3ms | 2000简单矩形短测59.6FPS，复杂场景待验 |
| 主线程单任务 | 常规≤8ms；>16ms工作拆分；避免>50ms长任务 | 给输入、绘制、浏览器调度留余量 |
| DOM | 一次更新建议≤100节点；避免每帧重建列表/整窗；长列表按需挂载 | 100/500/1000/3000节点构建2.7/16.2/21.1/48.8ms |
| Canvas | 静态地图/背景缓存，按需绘制；初始复杂动态对象≤500并实测再增加 | 简单矩形不是精灵、文字、阴影或物理模拟 |
| DPR | 实时游戏优先可调1–2；按实测选择，避免多张大画布 | RGBA缓冲占用随DPR平方增长 |
| Worker | 复杂纯计算可选；复用1个、限制队列，Transferable传输，退出terminate；短任务留主线程 | 单次启动12.4ms估计，1MiB往返0.3ms，非持续并发保证 |
| 回合制 | 不持续渲染；只在状态变化/必要倒计时刷新 | 适用三国身份战、王国争霸、棋牌 |
| 游戏通信 | 普通状态快照建议≤16KiB（软目标，绘画等特殊场景另测）；复用现有快照、ACK、背压 | 本机回环样本良好但跨机未验，不据此改变消息上限或频率 |
| 内存 | 先控制资源与缓存，不指定硬上限；关闭/最小化停止不必要绘制；检查20次反复打开关闭、30分钟稳定性 | 简化报告没有内存分配数据 |

## 仍需实测
- 两台 PAD 在获授权同网、统一客户端的连接与1/4/16/64KiB负载、实际 RTT、ACK 和积压；ICE checking 不能推断根因。
- 834×360真实宿主输入布局，拼音 composition、软键盘遮挡、双指越界、消息游戏切换。
- 后台切换60秒并确认 hidden>0/visibilitychange；另测页面被重建的情况。
- 内存与 JSON 测试结果可从完整报告或自动测试结果截图补录；30分钟及8台真实多人游戏回归。
