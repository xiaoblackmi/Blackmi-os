# Blackmi Game Runtime：MC 单文件源码研究与可行性分析

日期：2026-11-28 | 状态：Research / RFC（未实现、未验收） | 不属于正式发布路线承诺

## 0. 决策摘要

**GO：在现有 SDK 上按需构建轻量实时游戏工具层。NO-GO：把 MC 引擎直接纳入 SDK、用回合制接口硬做实时联机、为了移植游戏重写通信核心。**

最有价值的资产不是三维引擎，而是有界调度、输入抽象、固定步长、渲染与规则分离、资源生命周期、数据驱动和测量方法。先在两个不同类型的小型游戏原型证明复用价值，再引入公共接口；MC 仅作为后续独立压力研究样本。没有权利证明前不上传 MC 原始 HTML、素材或复制其实现。

## 1. 现有 SDK 与真实缺口

| 已有 V3.2.2 能力 | 缺口 / 设计原则 |
|---|---|
| BlackmiSDK.apps、mount / activate / deactivate / unmount | 不增加第二套生命周期或全局 RAF |
| ctx.onRender(draw) 合并 invalidate，前台绘制 | 卡牌、棋盘、静态 UI 直接复用，不再造脏帧框架 |
| ctx.onFrame(now,dt)，dt 上限100ms，返回取消函数 | 可选固定步长、分帧任务、采样性能工具 |
| ctx.listen / cleanup | 输入控制器与图形资源必须接入这些钩子 |
| ctx.storage，JSON 上限65536 JS 字符，仅会话 | 不承诺大地图持久化；不依赖宿主下载 |
| games.register，同步 createMatch/act/tick/publicFor/privateFor | 面向回合制，tick 约500ms，不是实时服务器 |
| 逐人快照、深冻结、ACK、故障清空，120000 JS 字符硬上限 | 不把快照当高频位置广播；16 KiB 是软预算，字符数不是字节数 |
| 受信任脚本在 HTML 解析阶段登记，bundle.cjs | 工具按需内嵌，零运行时依赖；不是动态插件、沙箱或外部网络 SDK |
| gameData:false（App 网络能力） | 不虚构通用 send/broadcast API；实时协议需独立 ADR、明确授权与审查 |

多人权威规则必须在宿主/房主侧维持必要逻辑，与客户端窗口可见性分开。关闭 UI 不应把房主的比赛计时和 RTC 维护一起关闭。回合制 UI 保持事件驱动，动画只是视觉表现。

## 3. 推荐架构（仅提案）

```text
游戏规则 / UI / 单独的 2D 或 3D 引擎
  ↓ 按需静态打包
Game Runtime helpers（纯计算、绘制辅助、输入、资源、性能）
  ↓ 复用现有 SDK
BlackmiSDK.apps / BlackmiSDK.games（回合制）
  ↓
现有 App 生命周期 / Lobby / GameLink / 聊天核心（冻结）
```

初期只写普通 JS 工具模块（建议 sdk/runtime/ 下独立文件），不必立即改变 BlackmiSDK 全局对象或版本。由 bundle.cjs 选择所需文件并在应用 mount 中创建实例。只有两个独立用例证明重复代码确实减少、成本可测后，再考虑正式命名空间与 d.ts。禁止通过修改聊天/Transport、ICE/SDP、QR、握手、消息上限来掩盖游戏性能问题。

### 3.1 P0：固定步长工具 + Profiler

接口草案（不是现有 API）：createFixedStep({stepMs,maxSteps,onStep,onDraw,onOverrun}) -> advance(now,dt), reset(), dispose()。调用方用 ctx.onFrame 驱动，禁止内部再申请 RAF。单机/纯视觉逻辑允许有限追帧并统计丢失时间；默认 20 或30 TPS 可选，非强制统一。插值只影响显示，不写权威状态。恢复前台清累积时间与输入，使用单调时钟；接受 dt=0/负值/NaN 时明确处理。

权威实时模拟另行设计：不允许因显示 FPS 不同而改变胜负/伤害；过载须降负载、报告、显式暂停或中止，不静默丢权威 tick。现有回合制 tick(now) 仍为房主约500ms 定时，不改其语义。

Profiler 有界环形缓冲：记录 frame interval、step CPU、render CPU、queue CPU、overrun、pending、最长任务；聚合 p50/p95/max、样本数、测试环境及丢帧。每秒或更低频更新诊断 UI，默认关闭/低开销。CPU 提交时间不等于 GPU 完成时间，帧间隔也不能等同设备内存或真实 RTT。

### 3.2 P0：协作式帧预算调度

接口草案 createTaskQueue({maxQueued,maxSliceMs,clock}) -> enqueue(key,priority,step), runSlice(budgetMs), cancel(key), dispose()。step(deadline) 返回完成/继续；任务必须可分割、版本化、可取消。按 key 去重，优先可见区域；低优先级通过 aging 防饿死。队列满拒绝/合并可丢任务，不能无界累积；新地图/对局 epoch 变化后旧结果丢弃。异常隔离并可诊断。

MC 在 L4666 允许预算超时仍至少生成一个区块，L4684 一次处理整区块，L4698 循环多个垂直段，因而 budgetMs 只是检查点，不是硬实时上限。研究版本应先做明确的分段工作单元，测试单次 step 超时并记录，不能声称 JS 可以强制抢占。首版主线程背景切片建议2–4ms，常规单任务≤8ms，>16ms 拆分，避免>50ms；以仓库软预算为准。先处理输入、必要逻辑和绘制，再执行低优先级任务，绝不延迟或丢弃 RTC 维护。

Worker 仅可选用于耗时纯计算；已有 1MiB Transferable 往返0.3ms、启动估计12.4ms 的短测不是持续吞吐保证。一个复用 Worker、有界队列、transfer 后原 buffer detach、返回值校验、超时/错误/过期结果丢弃、退出 terminate。无 Worker 或 Blob Worker 受宿主限制时回退分帧 JS。Canvas 仍主线程绘制，不依赖 OffscreenCanvas 或 SAB。

### 3.3 P0：容器化输入

接口草案 createInput(ctx,element,bindings) -> axis/action/pointer state、consumeEdges、reset、dispose。Pointer Events 优先（已有双指实测）；每 pointerId 按首次命中锁定角色，支持 capture、cancel、lostpointercapture、越界、触摸/鼠标去重、多指同时操作；deactivate、unmount、visibilitychange、blur 清状态。按 getBoundingClientRect 换算局部 CSS 像素，不以 window.innerWidth 代替窗口宽度；仅在游戏表面拦截默认动作，不拦截聊天、输入法、系统安全区。IME composition 期间不触发游戏快捷键。

连续状态（轴/按住）与一次性边沿（按下/释放）分离；一次边沿只消费一次，不能因同一帧追多个 tick 而重复执行。摇杆死区和灵敏度游戏配置；三国等点击型游戏继续用 DOM/ctx.listen，无需控制器。

### 3.4 P1：Graphics 与资源作用域

默认 Canvas2D；需要时双层画布：场景按比例缩放，UI 保持清晰，静态层按需绘制。画布 CSS 尺寸从应用容器实际边界读取，独立 backing buffer 分辨率，resize 后恢复绘图状态。动态画质用滞回与冷却时间防抖（例如连续采样数秒后降档，持续稳定再升档）；按实测选择 DPR 1–2、renderScale 0.5/0.75/1；不能把减少像素数量等同 FPS 提升。

WebGL 可选探测必须实际创建上下文并编译代表性 shader、绘制读回，检查 MAX_TEXTURE_SIZE、MAX_RENDERBUFFER_SIZE、MAX_ARRAY_TEXTURE_LAYERS（WebGL2）、GPU buffer 能力、扩展与 context loss/restore。MC 需要16×8032 垂直纹理 strip 的 Canvas 解码，以及502层数组；已测 WebGL1 纹理上限4096 不意味着 Canvas 上限也为4096，更不证明 WebGL2 支持。若纹理层不足，独立引擎用分图集/减少图层或明确不支持，不把 WebGL1 当作直接兼容。上下文恢复重建 GPU 资源，不能重置权威世界。资源所有权按应用/世界登记，关闭释放 buffer、texture、program、VAO、URL、监听、任务、计时器；处理迟到的异步加载，避免释放后回调。

### 3.5 P1/P2：种子、增量、资源与存档

- RNG：种子与算法版本明确，提供独立随机流（世界、AI、游戏规则、视觉分开）；固定测试向量、可序列化状态。回合制仅房主使用规则 RNG；不能向对手/观战者泄露可推导隐藏手牌的种子。它不是安全随机源。
- 增量：先用 ctx.onRender 与局部 DOM 更新；对棋盘、地图、图集定义 dirty key/rev 和相邻区域失效，不改网络协议。缓存有上限，重连/重开/主题和尺寸改变时全量失效。
- 资源：单 HTML、原创/授权小图集；生成资源清单（字节、解码尺寸、许可、哈希），避免同一资源重复解码。Base64 通常约膨胀1/3；压缩包体积不等于实际 HTML。按需解码，异常占位，关闭释放。AudioContext 实测 running 但用户没听到；声音完全可选，失败不影响规则。
- 存储：ctx.storage 只做小型设置/回合记录。世界种子 + 稀疏变更日志 + 版本号可用于未来有界会话存档，但导出、重启恢复尚无保证。RLE 与导入必须验证类型、整数范围、总长度、容量、版本和异常输入，原始/压缩两者选更小；不得把任意文件当可信 JS，不自动清除其他存储。大地图会话容量/可靠导入导出单独研究。

## 4. MC 独立移植可行性与压力模型

| 目标 | 判断 | 阻塞条件 |
|---|---|---|
| 通用工具层（不包含 MC） | 高，可独立开发 | 验证生命周期、性能与体积收益 |
| 原创小型二维/三维沙盒单机 | 中高，先小规模试验 | WebGL/Canvas 性能、触控、宿主窗口 |
| 高还原度主世界单机 | 条件可行 | WebGL2 能力未知、CPU/GPU 内存与存档未验收、素材权利 |
| 实时多人沙盒 2–8 人 | 当前不得承诺 | 通用实时接口缺失、跨机 RTC 未通过、状态模型与权威模拟需独立审查 |

定量模型（理论值，不是实机测量）：
- 单区块核心三数组：16×16×256×3 = 196,608 bytes =192KiB。还含颜色、群系、计数、网格、对象。R=8 的生成圆半径9.5约293块，仅核心约54.94MiB；R=3 半径4.5约69块、约12.94MiB。实际缓存保留至 R+4，移动时可能更大；128 高度约减半数组内存，但必须检查所有固定高度、分段位掩码、出生、矿物和海平面逻辑，不能只改常量。区块生成前先设置明确内存/数量上限。
- 960×600 DPR2 单 RGBA 缓冲约8.79MiB；DPR1 约2.20MiB；DPR1/scale0.75 约1.24MiB。双层、深度、浏览器合成和 GPU 驱动另计。当前 MC 的 32-bit 索引 262144×6×4 =6MiB，两个 MeshBuffer 初始 65536/16384×32 bytes 合计2.5MiB，说明小 HTML 不等于小运行内存。
- 默认视距8、世界高度256、主界面动态全景、全分辨率等不能直接作为 PAD 档。优先静态首页、3区块视距、限制高度/实体/任务数量、动态分辨率；先测，再决定是否采用 greedy meshing 或 Worker；本次未验证原文件使用贪婪网格算法。

多人另立研究：房主权威世界，客端仅动作意图；种子与算法版本一致才能重建基础地形；可靠方块变更需版本/顺序、冲突仲裁、幂等、快照校正、掉线与过期对局隔离，位置表现允许插值但不能替代权威裁决。发送范围按兴趣区域约束。数据格式、同步频率、传输路径和背压必须先以现有约束做负载模型及独立 ADR；不得假定当前回合制 submit 能承载高频动作，不改变 Transport。本文件不定义或新增协议。

## 5. 实施计划与验收关卡

不占用三国身份战分支，不指定必然发布版本。建议先有独立 runtime 实验分支（本研究仅文档），逐级批准：

| 阶段 | 最小交付 | 出口条件 |
|---|---|---|
| A | 独立固定步长/调度/Profiler，合成 Canvas2D demo | Node 虚拟时钟与队列测试，生命周期与旧 SDK 不冲突 |
| B | 触控工具、资源作用域，两个原创原型（移动类 + 回合/地图类） | 同功能对比：复用量、字节与性能；回合制仍按需刷新 |
| C | 可选图形缩放/能力探测与压力场景 | 实机 WebGL 能力/上下文恢复，2D 不承担3D成本 |
| D | 仅在前面通过后评估原创体素单机、有限存档 | 目标 PAD 30分钟、触屏、内存/资源回收、权限与素材授权 |
| E | 独立实时网络 ADR（不是本研究实现项） | 先获授权双机联通，基线与负载测试，再2/4/8人及断线恢复 |

体积初始目标（原始 minified UTF-8 JS，按实际打包差值测，不含图片、不以 gzip 冒充）：A ≤12KiB；B 新增≤12KiB；C 新增≤10KiB；按需加载，未使用模块零打包增量。不是已测体积或发布硬上限。超预算以实际功能和性能收益解释；若没有跨游戏复用证据，保留为游戏内工具，不扩大公共 SDK。

## 6. 试验矩阵与拒收标准

1. 纯逻辑：虚拟时钟注入，16/33/100ms、负值、长间隔、恢复、重复 start/dispose、maxSteps/overrun；同一输入时间序列在不同画面帧率得相同结果（只针对未过载模拟）。有界队列、去重、取消、优先级、公平性、异常、迟到 Worker 返回、超时及 fallback。
2. 输入：834×360 与960×600、DPR1/2，单/双/三指（第三指待实测）、移动+视角+按钮、手指越界/取消/失去 capture、缩放窗口、最小化、切换游戏、IME、宿主安全区；无粘键、无聊天输入吞事件。
3. 性能：同一版本、同一设备、固定种子/场景、热身后至少3次测量，记录测试时长、档位、p50/p95/max 帧间隔、CPU step/render、超预算次数、资源/队列计数。实时目标60FPS、低档至少稳定30FPS且关注 P95≤33.3ms；常规任务≤8ms；无持续长任务。静态游戏无持续 RAF/DOM 刷新。比较使用工具前后，不凭体感宣称提速。
4. 资源：打开关闭20次、切换后台60秒（必须记录实际 hidden/visibilitychange）、游戏30分钟，资源计数返回基线、无遗留 RAF/监听/Worker/URL、内存无持续增长迹象；如无可靠堆指标，标明未测，不编造绝对上限。注入上下文丢失、加载失败、Worker 失败、队列溢出；错误不能导致 OS 黑屏。
